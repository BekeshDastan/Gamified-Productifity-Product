# ADR-001: модульный монолит и детерминированные правила

Дата: 2026-10-12. Статус: принято на основании ТЗ 1.0.

## Контекст

ASCEND должен хранить личные данные, согласованно обновлять прогресс и давать
проверяемые объяснения каждого расчёта. Основное приложение работает без ключей
внешних сервисов. Нейросети исключены из продуктового стека требованиями ТЗ.

## Решение

- Next.js App Router / React / TypeScript strict для интерфейса.
- Go, chi, PostgreSQL, pgx, sqlc и goose для API и хранения.
- Отдельный worker того же монолита; задания и outbox в PostgreSQL.
- Один origin для web и API. Бизнес-правила и транзакции принадлежат Go API.
- Навигатор, расписание и отчёты используют фиксированные правила и формулы.
- Нет LLM SDK, embeddings, векторных БД, локальных моделей и AI-секретов.
- Внешние интеграции изолируются адаптерами и включаются по согласию.

## Последствия

Каждое вычисление можно воспроизвести тестом с фиксированными часами.
Необходимости в микросервисах, Redis или Kafka пока нет. Изменение решения
требует отдельного ADR и явного изменения ТЗ. Инструменты разработки не являются
частью пользовательского приложения.
