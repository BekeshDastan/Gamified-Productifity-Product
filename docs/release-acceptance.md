## Исправления, найденные полной регрессией

CI [39223071305](https://github.com/BekeshDastan/Gamified-Productifity-Product/actions/runs/39223071305)
на SHA `546ae27` подтвердил полный PostgreSQL-набор с race detector (413.656 с)
и 46/46 authenticated browser (528.274 с). Go проверки также прошли. В этом
запуске обнаружены две отдельные проблемы: ранний Tab до завершения начального
восстановления фокуса Next.js и healthcheck scanner через IPv6 localhost при
IPv4-only clamd. Проверка фокуса теперь начинается с готового элемента и
подтверждает переход Tab на ссылку; healthcheck проверяет PONG на 127.0.0.1.
Для объединения требуется новый полностью зелёный CI с этими исправлениями.

Повторные длительные локальные прогоны были прерваны лимитом времени после
длительной паузы хоста; они не считаются успешными. Приведённый полный результат
получен в независимом Linux CI, а четыре затронутых сценария также прошли локально.

Первый полный authenticated browser прогон: 43/46, три выявленных сбоя.
Они не объявлялись успешными:

1. Сохранение плана могло опередить загрузку добавляемой задачи. Пока задача
   загружается, форма блокируется; серверный снимок подтверждения сохраняет её.
   Сценарий сезонов теперь намеренно задерживает ответ загрузки задачи.
2. Первая задача при неверных часах устройства попадала на другой день.
   Быстрое добавление получает свежие серверное время и часовой пояс аккаунта;
   явная выбранная дата сохраняется. UX тест намеренно сдвигает часы устройства.
3. Отметка текущего периода привычки подставляла время устройства, отличное от
   серверного периода. Начальное время теперь берётся из as_of самой привычки;
   пользователь по-прежнему может указать другой момент явно.

## Ограничения перед публичным запуском

- Настроить сервер/DNS и проверить публичный TLS, SMTP STARTTLS, доставку
  подтверждения и восстановления пароля с реального домена.
- Подключить независимое хранилище, расписание backup и повторить restore
  с реальным объёмом данных на другой машине.
- Подключить Alertmanager/канал ответственного и проверить доставку сигнала:
  локальный Prometheus пока доказывает лишь firing/resolved.
- Browser push требует собственных VAPID-ключей и живого браузерного согласия;
  без них функция показывает недоступность. Локальные тесты адаптера не выдаются
  за живую доставку внешним push-провайдером.
- PostgreSQL в private compose-сети использует transport без TLS; для внешней
  managed DB требуется проверяемый TLS и отдельная настройка сети.
- Автоматические WCAG-проверки не заменяют ручную проверку screen reader.
