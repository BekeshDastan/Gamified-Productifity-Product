# Локальная производительность этапа 25

19 октября 2026. Windows, Go 1.26.9, PostgreSQL 17.11 в Docker Desktop.
Это измерение локального стенда, не SLA будущего сервера. Во время измерений
работали сборки/браузерные проверки, поэтому результат содержит шум.

`TestReleasePerformance`: отдельная случайная схема в `ascend_test`, 10 000 задач
одного владельца, 50 задач на день, сохранённый план с тремя приоритетами.
На маршрут 100 реальных HTTP-запросов, четыре параллельных клиента одной сессии.
Проверяются статус и полное чтение тела. Квота повышена только в тестовой фикстуре.

| Маршрут             | До p50/p95/p99, мс       | После p50/p95/p99, мс   |
| ------------------- | ------------------------ | ----------------------- |
| Dashboard           | 371.12 / 405.87 / 459.00 | 92.40 / 128.81 / 149.73 |
| Задачи, страница 50 | 57.46 / 71.10 / 80.38    | 53.28 / 71.33 / 79.90   |
| Календарь, неделя   | 76.80 / 94.49 / 100.70   | 55.14 / 70.77 / 81.51   |

Изменение: `planning.items` выполняет один запрос вместо N запросов.
`unnest WITH ORDINALITY` сохраняет порядок; JOIN ограничен владельцем;
недостающая/чужая задача возвращает 404, контейнер/архив проверяются как прежде.
Пустой план не обращается к БД. Никакие проверки наград/версий не ослаблены.

EXPLAIN ANALYZE BUFFERS для выборки задач дня подтвердил использование
`quests_planned` и `quests_parent`, 50 строк, 0.233 мс до изменения.
Дополнительные индексы без доказанной необходимости не создавались.
Проверяется существующая PostgreSQL-приёмка планов, подтверждения и изоляции.

Воспроизведение: задать TEST_DATABASE_URL на отдельную ascend_test,
RUN_RELEASE_PERF=1, затем из services/api выполнить
`go test -tags=integration -run '^TestReleasePerformance$' -count=1 -v ./tests/integration`.
Логи включают p50/p95/p99 и EXPLAIN; обычный CI не запускает нагрузку случайно.
Перед публичным запуском повторить на целевом сервере с ожидаемыми аккаунтами,
объёмом истории и конкурентностью. HTTP-замеры не являются замерами LCP/INP.
