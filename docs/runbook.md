# Локальная эксплуатация

## PostgreSQL

`compose.yaml` предназначен только для разработки. База слушает
`127.0.0.1:15432`, чтобы не конфликтовать с обычным PostgreSQL на 5432 и не
открываться в локальную сеть. Требуется явно заданный `POSTGRES_PASSWORD` в `.env`.
Dev-настройки нельзя переносить в production.

Запуск: `docker compose up -d --wait db`. Проверка: `docker compose ps`.
Остановка: `docker compose stop`. Данные сохраняются в volume `ascend-dev_pgdata`.
`docker compose down` также сохраняет volume. Не добавляйте `--volumes`: это
удалит данные. В проекте нет автоматического сброса основной базы.

Для интеграционных тестов будет использоваться отдельная временная схема/БД;
сброс допустим только для созданного этим тестом изолированного окружения.

## Файлы и тестовая почта

Приватные файлы: `.data/blobs`, за пределами web-root. Случайные ключи, ограничение
размера, SHA-256 и файловая граница `os.Root`. Прямого публичного URL нет.
Состояние quarantine нельзя считать clean при недоступном scanner: базовый
адаптер возвращает pending и ошибку. Реальный scanner подключается вместе с
пользовательским upload flow; сейчас этот flow не опубликован.

Mailpit 1.31.5: UI <http://127.0.0.1:18025>, SMTP `127.0.0.1:11025`.
Внешний relay не настроен; тестовые письма остаются локальными. В production
SMTP-адаптер требует STARTTLS и проверку сертификата. Plaintext разрешён только
на loopback в dev/test. Содержимое писем не журналируется.

## Миграции

`npm run migrate` / `make migrate` применяет только forward-миграции goose к
`DATABASE_URL`, явно заданному в локальном `.env`. Запускайте из корня проекта.
CLI не умеет очищать базу или выполнять down. Повторный запуск безопасен:
применённые версии хранятся в `goose_db_version`.

SQL и конфигурация генератора: `services/api/migrations`, `services/api/sqlc.yaml`.
Генерация с фиксированным sqlc 1.31.1 из корня в PowerShell:

```powershell
docker run --rm -v "${PWD}/services/api:/src" -w /src sqlc/sqlc:1.31.1 generate
```

Интеграционные тесты требуют отдельную БД с точным именем `ascend_test` и явную
`TEST_DATABASE_URL`. Они создают случайную схему на каждый тест и удаляют только
эту схему. `ascend_dev` и произвольные имена баз отвергаются.

Один раз создайте тестовую БД после `npm run dev`:

```powershell
docker compose exec -T db psql -U ascend -d postgres -c "CREATE DATABASE ascend_test"
```

Если база уже существует, повторно создавать её не нужно. Настройте
`TEST_DATABASE_URL`, `TEST_SMTP_ADDR`, `TEST_MAIL_HTTP` из `.env.example`, затем
`npm run test:integration`. Команда не пропускает проверки при отсутствии
настроек. `npm run check-changed` включает этот набор вместе с lint и unit tests.

CI создаёт отдельные контейнеры PostgreSQL/Mailpit и запускает интеграционные
тесты с race detector. Параллельные тесты получают независимые схемы. Неверная
миграция проверяется в тестовой схеме и не считается применённой.

## Ограничения текущего этапа

Backup/restore и production deployment ещё не подключены.
Готовность каждого пункта отмечается в ТЗ и журнале разработки.

## Авторизация и письма

AUTH_SIGNING_KEY — base64 32 случайных байт, общий стабильный ключ API и worker;
генерация без вывода в README. Значения не коммитить. В production обязательны
HTTPS и AUTH_INSECURE_LOCAL_COOKIES=false: cookie __Host-/Secure/HttpOnly/Lax.
Локальный HTTP допускается только явно и на loopback. Смена ключа инвалидирует
access/pre-auth и email/reset links; активные refresh sessions отзываются отдельно.
SMTP_HOST/PORT/MAIL_FROM нужны worker, SMTP_USERNAME/PASSWORD при аутентификации.
Production SMTP требует STARTTLS и проверку сертификата; локальная почта остаётся
в Mailpit, наружу не пересылается. Очередь допускает повторную доставку после
неопределённого SMTP результата, ссылки всегда одноразовые.

Пороги AUTH_LOGIN_FAILURES=5 (15 минут account+IP), AUTH_IP_FAILURES=50,
AUTH_REGISTRATIONS=10 (15 минут IP), AUTH_USER_REQUESTS=120 (минута user),
AUTH_MAIL_REQUESTS=3 (час), AUTH_TOKEN_ATTEMPTS=30 (час IP) настраиваются в окружении.
Почтовый лимит 3/час применяется к аккаунту/адресу; общий IP-порог выше
и задаётся AUTH_IP_FAILURES (по умолчанию 50/час), чтобы один адрес не исчерпывал
почтовую квоту других пользователей общего соединения.
Forwarded headers не принимаются: без отдельной настройки доверенного proxy
IP-лимит видит соединение proxy. Production-развёртывание ещё не принято.

Реальная браузерная приёмка: остановите dev, выполните npm run build:web,
затем npm run test:auth-e2e. Нужны ascend_test, TEST_DATABASE_URL,
TEST_SMTP_ADDR, TEST_MAIL_HTTP и Chromium. Порты 8080/3100 должны быть свободны.
Тест создаёт и очищает только случайную схему; рабочие аккаунты не создаются.

## Профиль и настройки

Forward migrations 00009–00014 добавляют профили, настройки, направления/теги
и сохраняемый онбординг без удаления пользователей. Триггеры создают обязательные
строки в той же транзакции регистрации. Новые поля preferences получают закрытые
defaults; обновление существующих настроек повышает version для защиты старых форм.
Изменения /me, /me/settings, /areas, /tags и /me/onboarding требуют If-Match.
При 409 интерфейс предлагает обновить данные; фоновые refetch не стирают черновик формы.
Смена пароля имеет отдельную квоту AUTH_LOGIN_FAILURES на 15 минут, после успеха
требует нового входа на всех устройствах. Preferences не публикуют личные записи.

IANA tzdata включена в Go binary. Даты входов и сохранения отображаются в timezone
аккаунта, рабочие интервалы — локальное время. Ночные интервалы/прошлые периоды
не пересчитываются автоматически. Календарный адаптер и напоминания будут использовать
сохранённый пояс при реализации своих этапов. Язык ru/en пока относится к датам.
Онбординг сохраняет явные черновики названий; будущие модули должны продвигать
onboarding_starters один раз по стабильному source ID, включая пропущенные шаги.

Браузерная приёмка теперь включает шесть сценариев, лимит тестового контекста —
6 минут, Go runner — 8 минут. Dev по-прежнему необходимо остановить перед сборкой
и запуском приёмки; production и dev используют общую папку .next.

## Вложения задач

Файлы хранятся вне web-root в BLOB_PRIVATE_DIR. По умолчанию UPLOAD_SCAN_MODE=unavailable: файл сохраняется в quarantine, скачивание запрещено. Для локального clamd с актуальными сигнатурами задайте UPLOAD_SCAN_MODE=clamav и CLAMAV_ADDRESS=127.0.0.1:3310; разрешён только loopback IP. StreamMaxLength не меньше 10 МБ. Ошибка, тайм-аут или неизвестный ответ не объявляют файл безопасным. После восстановления сканера владелец нажимает «Повторить проверку». Автоматический обход проверки отсутствует. Протокол: [ClamD INSTREAM](https://docs.clamav.net/manual/Usage/ClamdProtocol.html).

Лимиты: 10 МБ/файл, 5/задачу, 250 МБ/аккаунт. PNG/JPEG/WebP полностью декодируются с пределом 8192 по стороне и 16 млн пикселей. Имена не являются путями; выдача только владельцу, как attachment с nosniff и sandbox. Удаление сначала закрывает доступ в БД, затем удаляет объект; сбой последней операции может оставить недоступный orphan, который требует уборки по сверке хранилища. Тесты адаптера проверяют протокол на локальном тестовом TCP-сервере; живой clamd с сигнатурами в этой среде не запускался.

## Задачи и история

Forward migrations 00015–00021 добавляют задачи, представления, task_events,
подзадачи/зависимости, вложения и шаблоны. Обычный dev-запуск применяет их
без сброса рабочей базы. Плановая дата имеет тип date, дедлайн — timestamptz;
миграция 00021 переносит значения из payload и ограничениями защищает их
согласованность. Изменение timezone не сдвигает плановую календарную дату.

При первом открытии задач onboarding task draft продвигается один раз в той
же транзакции, с сохранением source ID; goal аналогично продвигается в разделе целей,
habit остаётся идеей до явного выбора нормы и расписания в разделе привычек;
стабильный source ID защищает создание из идеи от повторов.
Все изменения задач проверяют владельца и версию, переходы/шаблоны/batch также
используют ключ повторного запроса. Конфликт требует перечитать свежую версию;
не удаляйте ввод пользователя автоматически. Журнал хранит снимки и причины,
изменение блокировок — предыдущие/новые ID и названия.

Загрузка ограничена 10 МБ на файл. Предел multipart API — 11 МБ,
Next proxy — 12 МБ, чтобы служебные поля не отрезали допустимый файл.
Одновременно декодируются не более двух загрузок. Результат сканирования
пишется с проверкой версии; удалённый файл или более свежий результат не
перезаписываются запоздалой проверкой. Клиентский filename не используется
как ключ хранилища. Повторная проверка pending выполняется явно владельцем.

Полная browser-приёмка включает одиннадцать сценариев, без AUTH_E2E_GREP.
Для диагностики можно задать AUTH_E2E_GREP как регулярное выражение Playwright;
это ограничивает выбор тестов и не заменяет полный check-changed / CI.
Порты 8080/3100 и .next должны быть свободны от dev перед приёмкой.

## Цели

Forward migrations 00022–00024 добавляют цели, версии, этапы, связи и числовой журнал.
Тип прогресса задаётся явно: milestones / quests / metric. В quests считается
вес обязательных листьев, без повторного учёта контейнеров; вес этапа применяется
только при расчёте milestones. Необязательная ветка исключается целиком.
Связанные цели пересчитываются в транзакции события задачи под общей блокировкой владельца.
Перенос связи требует актуальной версии прежней цели и причины; пересекающиеся
родительские связи запрещены даже при последующем перемещении ветки.

Числовые значения хранятся с тремя десятичными знаками. Единица после первой
записи неизменяема. Исправление сохраняет исходную запись, причину и версии.
Пределы: 100 этапов, 500 прямых связей, 10000 записей на цель; история выдаётся
по 50 записей. Шаблон: не более 20 этапов и 100 задач, длительность 1–3660 дней.
Предпросмотр ничего не сохраняет. Подтверждённый шаблон создаётся атомарно;
даты вычисляются как календарные дни от выбранного начала.

Достижение требует 100% и подтверждения критерия. Прежний неверный результат
ниже порога создаёт goal.achievement_reverted и active. Срок вычисляется в
timezone владельца и не переводит цель в not_achieved. Для пересмотра требуется
будущая целевая дата; rebuild снимает связи и этапы, сохраняя задачи, журнал и
исторические снимки. Архивирование отдельно от состояния, восстановление
не выдаёт повторных наград. Экономика/HP будут подключены централизованно на этапе 11.

## Календарь (C057–C064)

Forward migrations 00025–00027 добавляют события, уникальные экземпляры серий,
исключения и неизменяемые журналы. Date-only планы/события и timestamptz блоки
не смешиваются; конец диапазона и all-day события исключён. Серия хранит свой
IANA timezone: смена настроек аккаунта меняет отображение моментов, сохраняя
wall time и ключ серии. Пропущенный час пропускается; двойной выбирает ранний
момент. Длительность timed блока — реальные минуты. 31-е в коротком месяце
пропускается. Серии ограничены 10 годами и 500 активными правилами на аккаунт;
недостижимый count отклоняется. Диапазон — максимум 370 дней/2000 отметок.

GET /api/v1/calendar создаёт максимум 400 недостающих экземпляров за транзакцию.
materializing=true явно означает продолжение: UI догружает диапазон до false.
Worker каждую минуту пополняет 60 дней тем же генератором. Общая блокировка
владельца и уникальная пара series_id/occurrence_key защищают от дублей HTTP/worker.
Ошибка истории откатывает также созданные задачи. Перезапуск worker безопасен.

Редактирование требует If-Match и Idempotency-Key. Перенос блока атомарно меняет
плановую дату той же задачи и её историю, сохраняя дедлайн. Изменение даты задачи
в её редакторе сохраняет отдельные блоки работы: у задачи может быть несколько.
Отмена повторяемой задачи записывает пропуск. Split сохраняет завершённые/архивные
экземпляры и явные отмены на прежней серии; продолжение исключает соответствующие позиции исходного плана, даже при сдвиге дат.
Сокращение серии отменяет только незавершённые будущие экземпляры. Увеличение конца
не восстанавливает уже отменённые экземпляры автоматически. История задач и дедлайны
доступны только для просмотра; пересечения блоков видны и остаются решением владельца.

## Планирование (C065–C072)

Forward migrations 00028–00030 добавляют планы, append-only изменения,
редактируемые шаблоны и уникальные применения по template/date.
Пояс сохраняется при создании плана. GET пустого дня не создаёт обязательств;
PUT с If-Match "0" создаёт черновик. Подтверждение сохраняет исходные задачи,
веса и блоки; последующие изменения требуют причины и не заменяют снимок.
Позднее выполнение не повышает выполнение прежнего календарного дня.
REST-день имеет NULL оценку. Без окон расчёт использует весь локальный день,
при этом лимит минут остаётся ограничением. Неизвестные оценки показаны отдельно.
Предпросмотр шаблона read-only, включая ещё не записанные повторы; apply сверяет
хеш версий и требует явного принятия пересечений/дефицита. Повтор не дублирует
задачи, уже применённые template/date пропускаются. Dashboard читает реальные
данные одним приватным запросом; состав виджетов хранится в настройках.

## Привычки (C073–C080)

Forward migrations 00031–00036 добавляют привычки, расписания, периоды, отметки,
исправления, паузы и интервалы архива. Рабочую базу не очищать. Периоды создаются
при чтении/создании не более 400 за запрос; has_more явно возвращается, интерфейс
продолжает загрузку. Курсор предотвращает повторный обход всей истории.

Пояс закреплён за привычкой. Недельные периоды начинаются в понедельник, месячные —
первого числа, конец не включён. Изменение нормы возможно только в будущем на общей
границе обоих расписаний и с причиной. Паузы не могут скрыть начавшийся или прошлый
период; экстренный пропуск текущего периода виден с причиной и временем,
не исключает начавшуюся норму из расчёта и не считается успехом.
Архив сохраняет историю, а возврат не создаёт обязательства за время архива.

Карточка показывает последние 120 периодов; полный журнал доступен страницами
60 периодов / 100 отметок. Исправления не удаляют исходное количество и время факта.
Начало новой привычки ограничено десятью годами назад / одним годом вперёд.
Повторная материализация безопасна, как и повтор отметки с тем же ключом запроса.

## Прогресс и награды (C081–C088)

Миграции 00037–00040 вводят неизменяемую economy-v1, права на награду, append-only ledger, расход rolling-квот и квитанции обработки проекции. Блокировки всегда: профиль владельца → user_progress → задача/привычка. Награда, исходная запись, баланс и outbox фиксируются одной транзакцией. Квоты считаются по серверному UTC за последние 24 часа: задачи 200, привычки 50, испытания 50, всего 300 XP. Отмена сохраняет использованную квоту; восстановление использует исходный снимок сложности, направления и суммы.

Первая полная норма привычки принимается до end + 24 реальных часа включительно. Поздняя отметка сохраняется, но новый XP не выдаёт. Исправление уже выданной награды компенсирует исходную сумму; отрицательные монеты показываются отдельной коррекцией и не позволяют положительную покупку. Пропуск сам по себе не списывает XP.

Проверка без изменений: `npm run reconcile:progression -- --all --dry-run`. Перестроение: `npm run reconcile:progression -- --owner=UUID` либо `--all`. Команда меняет только проекцию из суммы ledger, не выдаёт новые награды и не сбрасывает квоты. Перед массовой операцией сохранить резервную копию. Worker каждые 5 секунд забирает outbox, проверяет owner/ledger и создаёт единственную квитанцию. Повтор не начисляет XP.

## Персонаж и достижения (C089–C096)

Forward migrations 00041–00043 вводят каталог, профиль, инвентарь, версионированные определения достижений и историю изменений. Первые даты выдачи и снимки неизменяемы на уровне БД; исправление меняет активность права, сохраняя первоначальную запись. Невалидная экипировка после коррекции заменяется стартовым предметом; неполученный титул заменяется автоматическим.

20 оригинальных SVG встроены в API, выдаются только из whitelist по неизменяемому пути v1, не содержат скриптов или внешних ссылок. Лицензии: [каталог происхождения](assets/character-licenses.md). Владение и экипировка приватны. Условие предмета проверяется сервером при каждом изменении с If-Match и Idempotency-Key.

Worker обрабатывает character.changed и progression.reward_changed каждые 5 секунд. Чтение профиля/достижений дополнительно проверяет условия. История привычек материализуется не более 400 новых периодов за запрос; пока история не готова, зависимые условия недоступны для новой выдачи и ранее выданные не отзываются из-за неполной загрузки. Интерфейс показывает догрузку.

Служебный пересчёт: `npm run reconcile:character -- --owner=UUID` либо `--all`. Пакеты до 500 владельцев; незавершённая история одного владельца догружается ограниченными транзакциями, отмена — Ctrl+C, повтор безопасен. Пересчёт не создаёт XP и не тратит монеты. Команда восстанавливает проекцию баланса из ledger, сохраняет единственные выдачи и историю коррекций. Перед массовым пересчётом сохранить резервную копию.

Area XP — сумма дельт исходного направления ledger. Он уже включён в общий XP. Перенос завершённой задачи не меняет исходный снимок. Дерево навыков описывает активность в приложении. Рекорды берутся из исходных данных: лучшая серия, завершённые важные листья задач, регулярность ежедневных норм полностью закрытых местных недель. Фокус, сезоны и совместные испытания до подключения подтверждённых источников явно недоступны.

## Магазин, боссы и бесплатные подарки

Миграции 00044–00049 применяются вперёд без удаления пользовательских данных. Покупки сериализуются общей блокировкой кошелька владельца; постоянный operation UUID хранится отдельно от 24-часового кэша. Отменённая личная награда возвращает исходную цену одним ledger credit. Косметика и уже полученные личные награды не возвращаются. Корректировка старого заработка может сделать кошелёк отрицательным и не удаляет законно купленные предметы.

`mystery-v1` выдаёт по одному бесплатному праву за `goal-created-3` и `habit-created-3`; архивированные определения продолжают учитываться, поэтому правки не создают повторные подарки. Вес uncommon=3, rare=1. Перед первым открытием выбираются только ещё не полученные предметы; вероятность каждого равна его весу / сумме весов доступных. Если всё уже получено, начисляются ровно 5 виртуальных монет без XP. Каталог весов сохраняется в праве на подарок. Результат, постоянная выдача или credit записываются в одной транзакции до ответа клиенту. Повтор возвращает прежний результат независимо от текущего каталога/инвентаря.

Для остановки новых сюрпризов установить `FEATURE_MYSTERY_REWARDS=false` и перезапустить API и worker с одинаковой настройкой. Уже заработанные подарки открываются, полученные предметы сохраняются, магазин и основные награды продолжают работать. Платного случайного товара нет.

HP босса выводится из цели, без дополнительного XP. Победа выдаёт рамку/титул после подтверждения достижения; исправление достижения отзывает это право, а повторное подтверждение восстанавливает ту же выдачу. Историю этапов и критерий открывать через связанную цель. Главный босс привязан к календарному месяцу в часовом поясе профиля; выбор требует версии и явного месяца. Журнал хранит название, часовой пояс и причину прежнего выбора.

## Фокус и фактическое время задач

Миграции 00050–00052 добавляют фокус без сброса данных. На аккаунте допускается одна незавершённая сессия (running/paused/awaiting_confirmation). Постоянный operation UUID старта привязан к исходному запросу; версии защищают переходы между устройствами. Сервер хранит рабочие и перерывные интервалы и при чтении закрывает истёкший интервал на его границе. Дробные части длительностей интервалов отбрасываются до целых секунд; все сводки используют те же значения. Паузы не создают рабочий сегмент.

Свободная сессия ограничена 14400 рабочими секундами и 28800 секундами от старта. Pomodoro: работа 5–120 минут, перерыв 1–60 минут, каждый следующий интервал начинается по выбору. Короткий старт — пять минут с выбором завершить или продолжить ещё пять. Закрытие вкладки не создаёт бесконечного локального накопления. Отображение сверяется с сервером при возврате вкладки/сети, через polling и между вкладками; расхождение часов показывается отдельно.

После finish требуется result (progress/no_progress/rest) и необязательный комментарий. Повтор confirm сохраняет один итог. Отдых, отмены и ожидающие подтверждения сессии не входят в подтверждённую работу задачи. Таймер не меняет статус задачи и не создаёт XP. Для достижений focus-10/focus-50 подходят только подтверждённые progress-сессии с минимум 300 рабочими секундами; рекорд строится из подтверждённых сегментов, без отдыха.

`quests.payload.actual_time_mode`: `from_focus` берёт сумму подтверждённого фокуса, `manual_override` заменяет её `actual_minutes * 60`. Нельзя складывать эти источники. Старые ненулевые ручные значения мигрируют как override, нулевые — как from_focus; шаблон новой задачи сбрасывает фактическое время и возвращает from_focus. Для будущей аналитики использовать `focus.QuestTimeInTx` / API `/focus/quests/{id}/time`, которые явно возвращают источник и overridden.

Звук требует opt-in конкретной сессии и `personalization.sound=true`. GET current обновляет серверное разрешение звука, поэтому отключение на другом устройстве соблюдается при следующей синхронизации. История использует дату старта в сохранённом часовом поясе сессии, доступна только владельцу и показывает подтверждения/отмены/отдых отдельно. Закрытые сегменты, исходный запрос и окончательный результат защищены триггерами.

## Дневник и ритуалы C113–C120

Миграции 00053–00057 добавляют частный дневник, запуски/неизменяемые версии ритуалов, недельные предпросмотры/решения и личные чек-листы. daily_reviews — представление единственного evening run на владельца/дату; второй конкурирующий источник итогов не создаётся. Все маршруты требуют сессии владельца, административная роль не открывает чужие записи. Текст дневника и ответов не входит в outbox/jobs и HTTP-логи.

Markdown поддерживает заголовки, выделение, списки, fenced code и HTTP(S) ссылки. Raw HTML, изображения и встроенный контент остаются текстом; опасные схемы ссылок не исполняются. Редактор не исполняет содержимое записи. Черновики содержат только валидируемые поля формы в account-scoped sessionStorage текущей вкладки; нет токенов/паролей. Выход, отзыв сессии и смена аккаунта очищают все private drafts. Браузер может отключить storage: предупреждение о несохранённых изменениях продолжает работать.

Утро сохраняет существующий day_plan и подтверждает его атомарно с run; последующие изменения требуют причины и сохраняют первый подтверждённый snapshot. Вечер использует реальные листовые задачи/исходный план. Сохранённый разбор сохраняет свой timezone при смене настроек, а настроение/энергия необязательны. Смена шаблона не переписывает сохранённые ответы и чек-лист. За дневник и ритуал отдельного XP нет.

Weekly Reset: GET /reviews/week/{date}, POST /preview, затем POST /apply-plan. Дата — начало недели по настройкам. Preview живёт 10 минут, содержит до 500 исходных задач и версии; выбираются до 100 изменений и 7 будущих планов. Только подтверждённый apply меняет выбранные сущности. Дедлайны и фиксированные события не перемещаются. Конфликт/ошибка откатывает весь набор. Сохранённые decision/result постоянны и immutable: одинаковый повтор после истечения preview возвращает прежний итог; иное решение для того же preview даёт 409. Для нового решения нужен новый preview.

## Испытания C121–C128

Миграции 00058–00063 добавляют каталог, неизменяемые правила запуска, участие и интервалы, пересчитываемые источники, самоотчёты, согласия на файлы и итоговые снимки. API `/challenges/*` требует личной сессии. Каталог не создаёт задач. Принятие предложения на день/неделю создаёт одну задачу в «Идеях» с постоянным ключом владелец/период/начало/шаблон; подтверждённый план не меняется.

Зачёт использует первые квалифицированные task/habit entitlement, подтверждённые рабочие секунды focus, метаданные первого evening review и первое завершение milestone. Учитываются срок, замороженный timezone, дневной предел и интервалы участия. Повторное открытие снимает зачёт; восстановление использует исходный идентификатор/время. Старые завершённые этапы при миграции не получают выдуманного первого timestamp. Частный текст дневника и отметок не входит в задания очереди.

Ручная отметка создаётся только во время активного участия текущим днём пояса запуска и явно помечается self_report. Исправление сохраняет исходные дату, время и количество; новые действия требуют новой отметки. Файл выбирается среди собственных clean-вложений задачи. Видимость по умолчанию private; отдельное согласие participants и его отзыв записываются в историю. Само согласие не выдаёт download-разрешение: до социальной авторизации файл по-прежнему скачивает только владелец. Удалённый файл отображается как недоступный.

Worker обрабатывает `challenges.changed` по десять участников с продолжением и `challenges.close` на замороженный конец срока. Один профильный lock сериализует пересчёт и закрытие. Досрочное закрытие требует явного подтверждения и достигнутой цели. Закрытие сохраняет первый итог и страницы исходных источников; новые действия после него не расширяют запуск. Исправления прежних источников меняют текущий результат и отменяют/восстанавливают одно исходное entitlement. За выход, пустой запуск и таймер без результата XP не начисляется. Награда economy-v1 — до 25 XP, квота challenge 50 XP и общая 300 XP за скользящие 24 часа; остаток не переносится.

GET `/challenges/runs/{id}/progress` пересчитывает производные credits из собственных источников. GET `sources` показывает текущий зачёт, `final-sources` — неизменяемый первый итог. Восстановление проекции не меняет правила/первый снимок и не создаёт второго entitlement. Deadline jobs вставляются один раз; API не переписывает захваченные worker строки jobs, сохраняя порядок lock job → owner. Дополнительный scheduling clock используется только браузерной fixture с ускоренным временем; production хранит точный UTC конец запуска.

## Аналитика и отчёты C137–C143

Миграции 00069–00073 добавляют пересоздаваемые daily/weekly metrics, неизменяемые версии формул, происхождение новых копий шаблонов, личные ориентиры и снимки отчётов. `analytics.changed` обрабатывается тем же worker, что и другие outbox-события. API возвращает `computed_at`, ревизии источников и `stale`; UI явно показывает предыдущую сводку до пересчёта. POST `/analytics/rebuild` восстанавливает диапазон из рабочих записей. Ручное время задачи заменяет связанный фокус, отсутствие замера остаётся null. Отдых, отсутствие плана и невыполненный подтверждённый план различаются.

При запуске worker создаёт устойчивую часовую цепочку `analytics.reports_sweep`. Она ставит отдельные `analytics.reports_due` по владельцам пачками по 100; повтор bucket/owner не создаёт копии. Владелец обрабатывается под общим профильным lock, обновляет свой ранее запрошенный диапазон и формирует последние закрытые неделю/месяц при полных наблюдениях. До начала наблюдений нули не выдумываются. Смена зоны не переписывает прежние отчёты. Lease и весь снимок фиксируются одной транзакцией; повтор сохраняет первый результат.

Ручной предпросмотр отчёта действует 10 минут, проверяет ревизию источников и часовой пояс при сохранении. `operation_id` — постоянный UUID идентичности: повтор того же решения возвращает исходный отчёт даже после истечения transient cache. Изменение запроса с этим UUID даёт 409. Сохранённые снимки неизменяемы; после коррекции источника пользователь может создать новую ревизию. Для месячного сравнения берётся предыдущий диапазон с тем же числом календарных дней, а не месяц другой длины. При нулевой базе относительное изменение null, показывается абсолютная разница. Личные рекорды берутся из canonical character records на момент снимка; свободные тексты дневника и заметок метрик не выбираются.
