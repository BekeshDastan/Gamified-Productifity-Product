# Проверки текущей реализации

Реализованы C001–C064. Остальные пункты ТЗ ещё не считаются готовыми.

## Локальные наборы

- `npm run lint`: проверка секретов/генерируемых файлов, Prettier, ESLint,
  TypeScript, gofmt, vet, Staticcheck.
- `npm test`: проверки компонентов, контраста, keyboard/focus, форм и API-клиента, policy guard,
  конфигурация, HTTP envelope/лимиты/ошибки, доступ владельца/версии, privacy logs,
  shutdown, приватные blobs, SMTP security, тестовые HTTP clients.
- `npm run test:integration`: реальные транзакции PostgreSQL, повторяемые
  миграции, конкурентная идемпотентность, leases/retry/dead-letter/outbox,
  изоляция схем, отказ ошибочной миграции, локальный Mailpit.
- `npm run check-changed`: весь указанный выше набор; не пропускает существующие
  integration tests. Требует настроенного локального стенда.
- `npm run build`: production Next.js и Go API/worker.
- `npm run test:e2e`: production Chromium, 13 сценариев оболочки: 360/768/1280/1440 px
  в обеих темах, axe WCAG, keyboard, оба инициатора мобильного меню, system theme,
  persistence, API retry, 404/auth availability и reduced motion. UI fixtures
  не считаются проверкой реального API; Go integration проверяет БД отдельно.
- `check-changed` также собирает web и запускает E2E. Установить Chromium заранее.
- `npm run test:auth-e2e`: 13 production Chromium-сценариев с реальными Go API,
  PostgreSQL, worker и SMTP/Mailpit. Включён в `check-changed` и CI.

## Что уже проверено вручную

Стартовая страница dev/production и CSS возвращают HTTP 200. Общий dev-запуск
поднимает PostgreSQL, mail receiver, применяет forward migrations, запускает
API/worker/web. Остановка приложения сохраняет volume базы. Контрольная запись
пережила перезапуск PostgreSQL. Mailer доставил тестовое письмо в локальный
приёмник. Секретные значения не выводятся в диагностике приложения.

## Начало этапа 04

C025 проверяет серверную регистрацию без публичного HTTP endpoint: Unicode /
byte границы пароля, уникальные соли, постоянное сравнение хеша, отмену запроса,
недопустимые параметры PHC, недоверенные role/owner поля. Реальная PostgreSQL:
8 параллельных запросов создают 1 user и 1 audit, невалидный ввод не пишет данные,
ошибка audit откатывает account. Полный F01 и его E2E пока не завершены.

C026: реальные PostgreSQL-проверки входа, сроков 7/30 дней, истечения JWT на
границе 15 минут, актуальной роли, отзыва и изоляции двух владельцев. Проверяется
SHA-256 refresh в БД, отсутствие токенов в JSON и атомарный откат session при
ошибке audit. Unit-тесты отвергают неверные JWT claims/алгоритм/ключ и небезопасную
конфигурацию cookie. HTTP и браузерный вход ещё не подключены (C027/C031).

C027: HTTP с независимыми cookie jars; запросы без CSRF, с чужим Origin,
с чужой pre-auth cookie и неизвестной role отклоняются без создания аккаунта.
10 параллельных неверных входов: 5 × 401 и 5 × 429, Retry-After и восстановление
через 15 минут на управляемых часах. Успешный вход не расходует allowance ошибок.

C028: PostgreSQL + HTTP проверяют 8 одновременных refresh, единственный successor,
409 без cookie в grace 5 секунд, поздний reuse с сохранённым отзывом всей семьи,
независимость другого устройства, logout после истечения JWT, logout-all и
запрет отзыва чужой сессии. Потерянный Set-Cookie не восстанавливается повторным
refresh; требуется новый вход. Браузерные формы и синхронизация вкладок — C031/C032.

C029: реальная БД/outbox/worker с FakeMailer проверяют доставленный fragment link,
SHA-256 в token table, отсутствие raw token в jobs/outbox, срок 24 часа, одноразовое
конкурентное подтверждение и invalidate при resend. Проверены 3/час и rollback
регистрации при отказе очереди. RequireVerified блокирует действие до подтверждения.
Фактическая SMTP-доставка проверяется отдельным существующим Mailpit-набором.

C030: реальная PostgreSQL/worker проверяют нейтральный HTTP ответ known/unknown,
AES-GCM payload, только одно письмо известному адресу, reset 30 минут / один раз,
раздельные назначения token, смену пароля и отзыв двух устройств. Ошибка audit
откатывает password/token/session изменения. Forgot лимитируется 3/час email;
общий IP-порог 50/час, чтобы не блокировать пользователей общего соединения.

C031: production Chromium проходит весь цикл через Next proxy, реальный Go API,
PostgreSQL, worker и SMTP/Mailpit, без mock auth и ручной подстановки cookie.
Два независимых cookie jars, проверка reset-отзыва второго устройства, внешнего
redirect, HttpOnly/SameSite/remember-me и отсутствия token storage. Общий suite:
30 web unit + 13 UI E2E; отдельный запуск npm run test:auth-e2e. API logs проверены
на реальные пароли/cookie/token; слово password в имени безопасного route не секрет.

C032: 4 real-auth E2E (полный email/reset цикл; две вкладки с одним refresh и logout;
потерянный реальный ответ с повторным входом; 360 px и обе темы / WCAG). Unit-tests
проверяют pre-auth expiry/Origin/JSON/CSRF и игнорирование proxy headers. User quota
проверена на чтении и refresh с восстановлением окна; logout не блокируется квотой.
Конкурентность family reuse/one-time tokens и изоляция аккаунтов проверены в PostgreSQL.
Все браузерные и Go-проверки включены в check-changed / CI; старый UI suite использует
явные guest fixtures, настоящий auth suite не подменяет API и доставку SMTP.

## Приёмка этапа 06

32 web unit, 13 UI E2E и одиннадцать настоящих browser E2E. Три сценария задач
проходят сохранение всех полей и конфликт двух редакторов с сохранённым вводом;
start/complete/reopen/postpone/skip/fail и причины в истории; перенос без
молчаливого изменения дедлайна; подзадачу и сводный родитель; шаблон с preview;
сохранённые фильтры и одинаковые результаты списка/Kanban; пакетный архив и
восстановление с сохранением статусов. Светлая и тёмная темы проверяются в
360 px через axe и отсутствие overflow, скриншоты осматриваются отдельно.

PostgreSQL проверяет владельца для задач/связей/направлений/тегов/файлов/шаблонов,
If-Match двух одновременных редакторов, восемь конкурентных повторов завершения
с одним ключом и единственным событием, rollback при отказе журнала, глубину и
циклы, обязательные листья, каскад зависимых контейнеров при завершении/reopen
и снятии блокировки, причины и историю связей, атомарность batch и preview.
План хранится как date, дедлайн как timestamptz: типы и фильтры проверяются
в UTC/Asia/Almaty/America/New_York; нулевой год и чужие метки отклоняются.

Файлы: путь/чужой владелец/подмена MIME/повреждённые и чрезмерные изображения,
5 файлов и квота 250 МБ (метаданные в изолированной тестовой схеме), quarantine,
повторная проверка, безопасные заголовки выдачи и конкурентная версия сканирования.
Реальный браузер загружает TXT предельных 10 МБ через Next proxy, проверяет отказ
скачивания pending и HTML под видом PNG. ClamAV INSTREAM тестируется локальным
TCP-имитатором протокола, живой clamd с сигнатурами не проверен. Без него новые
файлы остаются pending; тестовый clean-сканер существует только в Go fixture.
Браузерная fixture использует 600 user requests/min для сжатого сценария;
рабочий default 120 сохранён и отдельно проверяется тестами HTTP-квот.
XP здесь не начисляется: централизованное начисление относится к этапу 11.

## Цели (C049–C056)

Девять PostgreSQL-сценариев проверяют CRUD/ownership/продвижение onboarding,
взвешенные этапы и листья, подтверждённый перенос, несовместимые единицы,
идемпотентность добавлений и завершения, неизменяемую историю исправлений,
предпросмотр шаблона без записи и переход календарного года. Событие задачи
и цель откатываются вместе при отказе журнала; смена родителя не обходит
запрет пересекающихся связей. Две параллельные правки дают один успех и один 409.

Сводка сравнивается с отдельной контрольной выборкой исходных весов. Вес этапа
не умножает веса листьев при типе quests. Числовой прирост 0.001 на старте
999999999.99 даёт ровно 10% при цели 1000000000. Срок проверяется в UTC,
Pacific/Kiritimati и America/New_York; смена зоны и наступление следующего дня
не закрывают цель и не меняют её версию.

Решения проходят от draft через active/paused до achieved/not_achieved/cancelled,
архива и восстановления. Порог не достигает цель автоматически; требуется
подтверждение критерия. Исправление отменяет ошибочное достижение с отдельным
событием. Пересмотр сохраняет прежние критерии и план, rebuild не удаляет задачи.

Два браузерных сценария проходят создание числовой цели, подтверждение,
исправление, конфликт двух окон с сохранением ввода, недостижение, архив,
восстановление и пересмотр; затем редактируемый шаблон, проверку дат,
подтверждение создания, выполнение и повторное открытие связанного листа.
360 px, axe и отсутствие горизонтальной прокрутки проверяются в обеих темах;
снимки интерфейса осматриваются отдельно.

Два browser-сценария проходят утреннее планирование, снимок, дополнение,
выполнение, отдых, шаблон и сохранение состава виджетов, axe/360 px.

## Привычки (C073–C080)

Проверки используют фиксированный предметный Clock и изолированные схемы PostgreSQL.
Три типа отметок, положительные нормы, собственные направления, версии расписаний,
дневные/недельные/месячные периоды, DST и местная граница недели проверяются отдельно.
Есть сценарии частичной нормы, количественного суммирования, 20 одинаковых запросов,
отката при ошибке записи, backfill и явной коррекции с сохранением исходного факта.
Серия пересчитывается после исправления; открытая норма и незапланированный выходной
не разрывают её. Будущие паузы, экстренный пропуск, несовместимая смена нормы,
архив/возврат, смена пояса, лимит 400 и страницы истории имеют серверные сценарии.

Два настоящих browser-сценария проходят через Next → Go → PostgreSQL: привычка →
две отметки → исправление → preview нормы → архив/возврат → Dashboard; и цель →
задача → календарный блок → выполнение → недельная привычка. Проверяются reload,
360 px, обе темы, axe и reduced motion. Бизнес-время фиксировано на 12 октября 2026,
а Clock авторизации и почты остаётся реальным, чтобы не замораживать срок сессии.

## Приёмка прогрессии C088

Проверять 20 параллельных завершений разных эпических задач (200 XP / 40 coins), 20 повторов одной задачи (одно право), повтор после истечения idempotency cache, откат отказавшей компенсации после расхода монет. Обязательны приватная история, снимок прежней сложности/направления, границы end + 24h привычки, квота UTC при смене пояса, rebuild повреждённого счётчика и повтор outbox.

Черновик новой нормы переживает отметку в другой форме; применение устаревшего предпросмотра отклоняется, введённые поля сохраняются до повторного просмотра.

## Приёмка RPG-профиля C096

Сервер: полный стартовый набор, whitelist SVG/MIME/cache, 401 приватных разделов, владение своего аккаунта, ограничение слотов, If-Match/Idempotency-Key, повтор входа, отзыв ошибочного unlock и fallback экипировки. Для каждого из 30 правил — fixture успеха, неуспеха и отсутствия доступного источника. Обязательны повтор события, массовый пересчёт, rollback отказавшей выдачи, неизменность первых дат и недоступность вымышленных будущих источников.

Рекорды: семь полных ежедневных норм прошлой недели дают серию 7 и регулярность 100%; исправление последней нормы до нуля даёт 6 и 85%, отзывает связанный титул. Чужие/неполученные титулы отклоняются. Десятилетняя пустая история не создаёт успехи; догрузка одного чтения ограничена 400 периодами, служебный пересчёт завершает её.

Реальный браузер: первая важная задача выбранного направления → достижение → доступный аксессуар → надевание с клавиатуры → выбор титула → выход и повторный вход. Проверяются сохранённый образ, источник рекорда, открытые/закрытые узлы дерева, список условий, обе темы на 360 px, axe и reduced motion. В очередь не должны попадать dead jobs производных профилей; пароли не должны появляться в API-логах.

## Приёмка магазина, боссов и сюрпризов C104

- PostgreSQL: две покупки при балансе на одну; повтор permanent operation ID после истечения 24-часового кэша; исходная цена после редактирования; запрет чужого владельца.
- Возврат только pending custom: компенсация ровно исходной стоимости, повтор/claim не возвращает монеты; сбой ledger откатывает решение вместе с кошельком. Снимки покупки и итоговые решения защищены триггерами.
- Босс: HP из обязательных этапов цели, ноль HP до подтверждения критерия не означает победу; отмена результата симметрично пересчитывает HP/титул/рамку; восстановление переиспользует прежнюю выдачу без второго XP.
- Босс месяца: два параллельных выбора дают один успех, смена месяца создаёт новый слот и сохраняет журнал; устаревший месяц и чужой босс отклоняются.
- Mystery: границы взвешенного выбора, 12 одновременных открытий дают один результат/предмет; повтор через 25 часов не перевыбирает; единственный отсутствующий предмет выбирается обязательно; полный набор даёт один credit 5 монет без XP. Отключение новых выдач сохраняет заработанные подарки.
- Реальный браузер: нехватка монет, подтверждение покупки, отмена/возврат, повторная покупка и получение, сохранение после перезагрузки; бесплатный подарок с клавиатуры, босс/месяц/главная/победа/исправление. Светлая и тёмная темы, 360 px, reduced motion, axe WCAG A/AA.

## Приёмка концентрации C112

- Два независимых клиента: один старт, одинаковая сессия и время; stale version даёт 409, повтор pause/finish не накапливает время.
- Серверные границы: 4 часа активных интервалов, 8 часов от старта, задержанный GET после закрытой вкладки, точный cutoff и исключение пауз/перерывов.
- Pomodoro: работа 5–120 минут, перерыв 1–60 минут; после границы нужен явный выбор следующего интервала. Короткий старт останавливается через пять минут и не завершает задачу.
- Confirm: только awaiting_confirmation, одинаковый повтор возвращает исходный итог даже после суток; иной итог даёт 409. Failure injection доказывает откат состояния и производного времени вместе.
- Источники: from_focus использует только подтверждённые рабочие интервалы, manual_override заменяет их ручным итогом; отдых/отмены/неподтверждённые сессии исключены. Задача не закрывается, XP не добавляется.
- История: суммы строк совпадают с суммой сегментов; фильтры дат/задач/направлений/состояний, приватные курсоры, архивные задачи и индивидуальные ссылки на сессии.
- Реальный браузер: reload, две вкладки, pause/resume/finish/confirm, ручной источник, пяти­минутная кнопка в задаче, Pomodoro work/break, отключённый звук, 360 px обе темы, reduced motion, axe WCAG A/AA.
- Только в изолированном браузерном fixture часы фокуса ускорены в 60 раз, чтобы проверять реальные серверные границы без пятиминутного ожидания. Production использует RealClock; API-моки таймера отсутствуют.
